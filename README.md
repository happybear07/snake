# 도토리 스네이크 (Acorn Snake)

방향키로 다람쥐를 움직여 먹이를 먹으면 꼬리가 길어지는 스네이크 게임. tkinter 로 만들었다.

5주차에 만든 게임에 **PokeAPI** 를 붙여, 먹이가 갈색 네모에서 **실제 포켓몬**으로 바뀌었다.
매번 다른 포켓몬이 나오고, **포켓몬 타입에 따라 먹었을 때 벌어지는 일이 달라진다.**

기획안은 [`api-plan.md`](api-plan.md) 에 있다. 5주차 기획안은 [`plan.md`](plan.md).

## 실행

```powershell
git clone https://github.com/happybear07/snake.git
cd snake
uv run python acorn_snake.py
```

**API 키는 필요 없다.** PokeAPI 는 인증 없이 쓸 수 있는 공개 API 라서 `.env` 파일도 쓰지 않고,
저장소에 비밀 정보가 들어가지 않는다.

조작은 5주차와 같다 — 방향키로 시작·조종, 스페이스로 일시정지, R 로 다시 시작, X 로 종료.
최고 점수는 `acorn_highscore.json` 에 저장된다.

## 파일

| 파일 | 하는 일 | 줄 수 |
|---|---|---|
| `acorn_snake.py` | 게임 — 화면, 입력, 게임 루프, 충돌, 점수 | 200 |
| `pokemon.py` | PokeAPI — 호출, 응답 파싱, 실패 처리, 미리 받아 두기 | 84 |
| `api-plan.md` | 이번 과제 기획안 (무엇을 만들고 무엇을 안 만들지) | |
| `plan.md` | 5주차 기획안 | |
| `verify_checklist.py` | 두 기획안의 체크리스트 22개를 자동으로 확인하는 스크립트 | |
| `verify_result.txt` | 위 스크립트를 돌린 결과를 그대로 저장한 것 | |

둘로 나눈 이유: 네트워크가 끊겨도 게임은 그대로 돌아가야 하므로, API 쪽에서 실패를 전부
삼키고 게임 쪽에는 "포켓몬 하나" 또는 "없음(None)" 만 넘긴다. 게임 코드에는 `requests` 가
나오지 않는다.

## requests 는 왜 필요한가

이번에 처음 넣은 외부 패키지이고, 하는 일은 두 가지다.

1. **API 호출** — `https://pokeapi.co/api/v2/pokemon/{번호}` 를 불러 `.json()` 으로 딕셔너리로 바꾼다.
2. **스프라이트 PNG 다운로드** — 그 응답의 `sprites.front_default` 주소에서 96×96 PNG(600바이트 안팎)를 바이트로 받는다.

`requests.Session` 을 하나 만들어 돌려 쓴다. 같은 서버에 여러 번 요청하므로 연결을
재사용하는 쪽이 빠르다. 모든 요청에 `timeout=5` 를 준다.

이미지 처리 라이브러리(Pillow)는 **쓰지 않는다.** Tk 8.6 의 `PhotoImage` 가 PNG 를 그대로 읽고,
`subsample(4, 4)` 로 96px 을 격자 한 칸인 24px 로 줄이면 딱 맞는다.

## 어떻게 돌아가는가

**켤 때.** 창이 먼저 뜬다. 네트워크를 기다리지 않는다. `Feeder` 가 백그라운드 스레드에서
1~151번 중 무작위로 8마리를 받아 큐에 쌓는다. 아직 받아온 게 없으면 먹이는 5주차와 같은
갈색 네모이고, `poll_mon()` 이 300ms 마다 도착했는지 확인해 한 마리라도 오면 그림으로 바꿔
다시 그린다. 실제로 켠 뒤 **2~3초**면 포켓몬이 보인다.

**먹이를 먹을 때.** 그 포켓몬의 첫 번째 타입에 따라 셋 중 하나가 일어난다.

| 타입 | 일어나는 일 |
|---|---|
| `electric` | 점수 +1, 길이 +1, 그리고 **25틱 동안 속도 2배** (틱 간격 110ms → 55ms) |
| `rock` `ground` `steel` | **점수 +2, 길이 +2** — 무거운 대신 많이 준다 |
| 그 외 전부 | 점수 +1, 길이 +1 (5주차와 같음) |

길이를 2 늘리는 방법은 `grow` 를 1 로 두는 것이다. 다음 한 틱 동안 꼬리를 떼지 않으므로
머리가 하나 늘어난 만큼이 그대로 남아 결과적으로 2가 된다.

먹은 뒤에는 큐에서 다음 포켓몬을 꺼내고, 뒤에서 한 마리를 더 받아 큐를 채운다.
점수바에는 지금 먹이가 무엇인지 `점수 3 · 최고 7 · dugtrio(ground)` 처럼 나온다.

**끌 때.** 받아오던 스레드를 멈추고, 예약된 루프를 취소하고, 최고 점수를 저장한 뒤 닫는다.
받아오는 중에 닫아도 창은 기다리지 않는다 (`daemon=True`).

**이미지 참조.** `PhotoImage` 는 파이썬 쪽에서 참조를 놓으면 그림이 치워져 **빈칸으로 보인다.**
그래서 만든 이미지를 `self.sprites` 딕셔너리에 이름별로 보관한다.

## 안 될 때

게임이 멈추거나 오류로 죽지 않게, 네 경우를 모두 기본값으로 넘긴다.

| 상황 | 어떻게 되는가 |
|---|---|
| 인터넷이 없다 | 큐가 비어 있으므로 갈색 네모로 끝까지 플레이된다. 점수바에 포켓몬 이름이 안 뜰 뿐이다 |
| 응답이 느리다 | `timeout=5`. 게임 루프와 다른 스레드라 화면은 멈추지 않는다 |
| 응답이 깨졌다 | `try`/`except` 로 그 한 마리만 버리고 다음을 받는다 |
| 스프라이트가 `null` 이다 | 그 포켓몬은 건너뛴다 (스프라이트가 없는 포켓몬이 있다) |

## 환경 재현

`uv` 가 `pyproject.toml` 과 `uv.lock` 으로 환경을 만든다. `.python-version` 에 3.12 가 적혀 있다.

```powershell
Remove-Item -Recurse -Force .venv      # 가상환경을 아예 지우고
uv run python acorn_snake.py           # 다시 실행
```

지운 상태에서 위 명령을 돌리면 uv 가 가상환경을 새로 만들고 `requests` 와 그 의존성
(`certifi`, `charset-normalizer`, `idna`, `urllib3`)까지 **5개 패키지를 1.7초에 설치**한 뒤 실행했다.
`pip install` 을 따로 할 필요가 없다.

## 기획대로 되는지 확인한 것

두 기획안의 체크리스트 22개를 `verify_checklist.py` 가 확인한다. 방향키·스페이스·R 은
`event_generate` 로 실제 KeyPress 를 창에 보내고, 루프는 실제 시간을 흘려보내 돌린다.

```powershell
uv run python verify_checklist.py
# -> passed 22/22, 자세한 내용은 verify_result.txt
```

**22개 전부 통과했다.** 결과 원문은 `verify_result.txt` 에 있고, 몇 줄만 옮기면 이렇다.

```
[O] 15  창 뜨는 데 0.358초(<1초), 2.7초 뒤 포켓몬=ekans, 캔버스 image 요소=1개
[O] 16  점수바=['점수 0 · 최고 0 · dugtrio(ground)']
[O] 17  electric: 점수 0->1, 길이 3->4, 남은 가속 틱=24, 틱 간격 110ms->55ms
[O] 20  연달아 받은 4마리=['nidorina','primeape','venomoth','tentacruel']
[O] 21  인터넷 끊김: 예외=None, image 요소=0개(갈색 네모), 먹으면 점수+1=True
```

21번은 `requests.Session.get` 이 무조건 실패하도록 바꿔 놓고 돌린 것이다. 1~14·17~19·21번은
네트워크를 끊고 돌려서, 5주차 동작이 API 와 상관없이 그대로인 것도 같이 봤다.

검사와 별개로 직접 켜서 플레이해 봤다. 켠 뒤 몇 초면 먹이가 포켓몬으로 바뀌고, 먹을 때마다
다른 포켓몬이 나오고, 점수바의 이름과 타입이 따라 바뀐다.
